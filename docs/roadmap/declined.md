# Declined

Rejected ideas and epics, kept so they are not proposed again. One line each: ID, name, why. How they get here: [maintainer/roadmap.md](../maintainer/roadmap.md), **Roadmap rows**.

| ID | Item | Why declined |
| --- | --- | --- |
| I42 | <a id="I42"></a>Sidekick joins captive-portal networks (hotel/conference WiFi) | Declined 2026-09-24: its own provisioning captive portal already failed (retired 2026-09-21), and nothing on the sidekick needs an uplink; the phone clears venue portals itself. Revisit only if a field session shows the sidekick needs outbound internet. |
| I17 | <a id="I17"></a>M32 Pocket as Micro-FT8 host | Declined 2026-09-25: the P4 + sidekick is the direction; the Pocket needs unproven external hardware to host a radio. RFC 0003, which also proposed BLE time sync: `git show 4832e4f:docs/rfcs/rejected/0003-m32-pocket-port-and-ble-time.md`. |
| I16 | <a id="I16"></a>Optional TX meter poll off | Declined 2026-09-25: no observed CAT-load symptom; reopen if a late `TA` or USB glitch is traced to the poll. |
| ujk5 | <a id="ujk5"></a>Autoseq: stop resending RR73 when DX is heard calling CQ or working another station | Declined 2026-10-11: ROGERS now sends RR73 once and parks right after it, before DX's next slot is decoded, so there is no resend left to stop; it would also have needed autoseq to see decodes not addressed to us. |
| qdcm | <a id="qdcm"></a>A P4 reset leaves the QMX unenumerated until it is replugged | Declined 2026-11-02: the wedge is the QMX's, and only the QMX clears it; the P4 cannot switch the Host port's 5 V, and a root-port cycle re-enumerates into the same wedge ([main_board.md](../architecture/main_board.md), **Host**). |
| p83e | <a id="p83e"></a>Home decode server: stream P4 audio to a LAN host running `jt9` | Declined 2026-11-03: paired data comes from recordings scored offline (the [2026-11-02 IQ/audio corpus](../../tools/decode_bench/corpus/qmx-2026-11-02/README.md)), and `jt9` feeding autoseq competes with keeping decode on the P4. RFC 0012: `git show 4832e4f:docs/rfcs/rejected/0012-home-decode-server.md`. |
| B85 | <a id="B85"></a>Measure QMX out-of-band audio; anti-alias decimator if it costs >1 dB | Declined 2026-11-03: the QMX decodes only from IQ mode, whose front end filters before it decimates; the unfiltered audio resampler is gone. |
| B57 | <a id="B57"></a>Radio auto-detect: tell a QMX from a QDX over CAT | Declined 2026-11-03: the QDX is dropped (maintainer), so there is no other radio to tell a QMX from; reading the QMX's bands is [vcng](../ROADMAP.md#vcng)'s. |
| ujnx | <a id="ujnx"></a>HL2: step the LNA back up when the band quiets | Declined 2026-11-05: stepping back up pays only if lower gain costs decodes, and the [2026-11-05 run](../../tools/decode_bench/corpus/hl2-2026-11-05/README.md) measured none: 40 m after dark held at +20 and +14 dB in alternate slots decoded 48.8 and 49.0 a slot (paired −0.43 ± 1.06), though +20 dB flagged a clip in 42% of status words, and 10, 15 and 20 m at +8 dB matched the one-band survey at +11 to +17 dB. Revisit if a band or antenna shows a cost from lower gain (a quiet 10 m on a short antenna is the likeliest). |
| zdmr | <a id="zdmr"></a>HL2: show the operator the LNA's gain and overload | Declined 2026-11-05: the [2026-11-05 run](../../tools/decode_bench/corpus/hl2-2026-11-05/README.md) found the gain from +5 to +20 dB does not move decodes, so a gain readout is a number the operator cannot act on. The slot bar's overload flag, shown when the LNA is at its floor and still clipping, is the case worth showing and stays. Revisit with [ujnx](#ujnx). |
| wdw5 | <a id="wdw5"></a>A QSO harness from simulator to the air, replaying recorded sessions and filming them | Declined 2026-11-05: it covers the autoseq engine, already the best-tested part (`host_mock`, `sim_station`, `decode_recall`, `tx_e2e`), and leaves out the bugs that bite (USB, WiFi, mismatched builds); goldens of a pre-alpha UI and autoseq break on every intended change, at the maintainer's time. Its useful parts are rows [qk2c](ideas.md#qk2c) and [cfr9](ideas.md#cfr9) and epic [u8mc](several-channels.md)'s replayed HL2. |
| efud | <a id="efud"></a>A BLE companion: the phone talks to the station over Bluetooth | Declined 2026-09-25: same-chip NimBLE beside the QMX's USB host failed its DMA-memory gate (2026-08-31), and the phone reaches the station through the sidekick's WiFi and HTTP instead ([system.md](../architecture/system.md)). RFC 0001: `git show 4832e4f:docs/rfcs/rejected/0001-ble-companion.md`. |
| gjsq | <a id="gjsq"></a>One station core shared by both main boards | Declined 2026-10-02: the ADV was dropped, so there is one main board and no second copy of the CONFIG path to unify; the P4's `StationSettings` is the only one. RFC 0011: `git show 4832e4f:docs/rfcs/rejected/0011-station-core.md`. |
| xeqt | <a id="xeqt"></a>ADIF: `TIME_ON` with seconds, at the QSO's start, and `TIME_OFF` | Declined 2026-11-10: no consumer needs it. LoTW matches within 30 minutes and POTA by date, band and mode; two QSOs in one minute are different calls, and the 10-minute dedupe stops the same call twice. The P4's file keeps seconds, but the Port A row carries `HH:MM` ([logging.md](../architecture/logging.md), **The four-place field chain**), and widening it costs bytes [j27m](ideas.md#j27m) and [w5nj](../ROADMAP.md#w5nj) want. Seen when N6UA and N5BY, worked 30 s apart, exported as 2154 both. |
| I6 | <a id="I6"></a>Multi-mode product (a name that is not FT-only, JS8Call as a mode) | Declined 2026-11-13: FT4 runs beside FT8 at runtime (epic [u8mc](several-channels.md)), which was its first step; JS8's coding tables exist only in JS8Call (GPL-3), so a JS8 mode would make the firmware we distribute GPL-3, and a rename with no third mode names nothing. A further mode needs its own MIT implementation and its own row. |
| I38 | <a id="I38"></a>Max-decode main board: Raspberry Pi Zero 2 W running `jt9` | Declined 2026-11-13: 1.0 trades decode depth for size, low power and cost, and says so ([release-1-0.md](release-1-0.md), **Constraints**); a Linux board with a 30 s boot and an SD card gives that up, as [p83e](#p83e) would have. |
| I25 | <a id="I25"></a>Static DIRAM/IRAM budget ratchet in CI | Declined 2026-11-13: a gate with no regression behind it, on the RAM that does not decide anything; the RAM that matters is the largest DMA block in a live session ([main_board.md](../architecture/main_board.md)), which no build can know. Headroom shown without a gate is [b5bh](ideas.md#b5bh). |
| w859 | <a id="w859"></a>The app says when it does not match the sidekick's firmware | Declined 2026-11-13: a bench hazard, not an operator's. The one case seen (2026-10-30) was a branch whose app used an endpoint without raising `api_min`, which the install gate would have refused; an operator's app and firmware arrive by one Update ([antu](ota-updates.md#antu)), and a bench pass confirms its three builds first ([TEST_PLAN.md](../TEST_PLAN.md), **Pending**). |
