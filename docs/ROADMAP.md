| hvz8 | Sidekick: lock the Port A reply state (race) | **Defect.** Reply state shared by `porta_rx_task` (writer) and HTTP handlers (readers, via `wait_action_reply()`) has only `volatile` + a 25 ms poll, though `s_lock` (`host_link.c:110`) already guards the ring. Worse, the verb is published first (`:1027`) and OK/reason after (`:1067–1074`), so a waiting handler can read the previous reply's OK: a NAK reported as success, or the reverse — even on one core.
