# Micro-FT8 roadmap

Living plan for Micro-FT8. How it is kept: [maintainer/roadmap.md](maintainer/roadmap.md). The rest of `docs/`: [README.md](README.md).

How things work now: `architecture/` (start at [architecture/system.md](architecture/system.md)). An epic's detail is in its file under [roadmap/](roadmap/); unscheduled ideas are in [roadmap/ideas.md](roadmap/ideas.md), rejected ones in [roadmap/declined.md](roadmap/declined.md).

| vcng | <a id="vcng"></a>QMX: read the radio's model, bands and PTT outputs over CAT | At link-up the P4 reads `OM;`, `VN;` and the Menu Manager's "Band config." table: each band's Transmit flag and four PTT output flags (QMX CAT manual 1_04_004), which leaves the radio where it was ([radio.md](architecture/radio.md), **Reading the menus over CAT leaves the radio where it was**). A band without the Transmit flag, or marked listen-only, never transmits, amplifier priming included (it keyed 60 m on 2026-11-03). Settings › Amplifier names how the amp is keyed (none, TX PTT grounded, TX PTT +5V) and warns per active band where the flags disagree; a Micro PA100+ takes grounded alone (QMX 1_04_010, 2026-11-09). Keyed from PTT, System config › GPS & Ser. ports › **Serial 6 on PTT** must read Disabled (it makes the jack a UART), else Settings warns. `long-ok` (maintainer, 2026-11-09). **Done-when:** the table and PTT flags read match the radio's screen (field); Settings offers only those bands, a transmit on a band without the flag is refused, and the PTT warning shows and clears, host-tested. |

| dlu3 | <a id="dlu3"></a>Sidekick: the web server stalls the app | The server runs one request at a time. Built: slow requests logged; events replies batched (a whole-ring reply 2.6 s to 0.2 s at worst; [sidekick.md](architecture/sidekick.md), **Port A**). Left: `/api/config` can still wait up to 5 s on the P4 over Port A (`wait_reply()`), as on 2026-11-07 after a band change and with the QMX off the P4; a client that falls behind the ring skips events silently, as `/api/state` could resync it to the present; per-slot logs fill the ring and belong on the P4's console; and the sidekick on Port A power may be short of supply (a meter is ordered). A slow client holds the server while replying. Files are `no-store`, no `ETag`: each load and each page's minute `checkAppStale()` refetch 155 KB; serve bundle version as `ETag`, `no-cache`, 304s. Not core placement ([wgjx](roadmap/ideas.md#wgjx)). **Done-when:** with the QMX unplugged and through a band change, `/api/config` and `/api/events` answer within 500 ms, and the app shows no "No contact" (field). |
| v697 | <a id="v697"></a>The sidekick updates itself over the air | Epic [ukk6](roadmap/ota-updates.md#v697). The web app hands the sidekick an image's URL, size and SHA-256 from the manifest; the sidekick downloads it over plain HTTP into its spare OTA slot, refuses a wrong hash, and restarts into it. **Done-when:** a sidekick updates from the web app; a forced bad image rolls back (field). |
| tnrr | <a id="tnrr"></a>Queue entries carry their mode, dial and TX offset; the row shows the mode | Epic [u8mc](roadmap/several-channels.md#tnrr). Port A's `QUEUE_ENTRY` carries no mode, so Operate cannot say which queued stations are FT4 and which FT8; on 20 m (2026-11-10) that hid FT4 calls transmitting over an FT8 QSO's reply slots. The event gains the entry's mode, dial and offset (protocol v16); the row shows the mode, and the dial and offset wait in the JSON for several channels. Before [bdy4](roadmap/several-channels.md#bdy4), which needs the mode on the wire. **Done-when:** `host_test_porta_proto` pins the layout and a host test shows an FT4 entry's event carrying FT4's mode and dial; an FT8 and an FT4 entry queued together show their modes on Operate (field). |
| jtg9 | <a id="jtg9"></a>Refuse Call CQ and a reply with no radio ready | **Safety.** With no radio, a CQ is accepted and queued; each of its slots is skipped as "CAT not ready" and a skipped slot is not counted, so it never expires, and it keys by itself when a radio is plugged in, however much later (read from `tx_start()`, `poe_p4/main/tx_scheduler.cpp`; bench 2026-11-12, maintainer: "it should not be possible to call CQ with no radio connected and decoding"). **Fix:** the main board refuses `CQ_CALL` and `QUEUE_REPLY` unless CAT is up and audio is arriving, with the reason in the radio bar's words, as Tune already does; the app shows it as a toast. A CQ already running when the radio drops is [u4dw](#u4dw)'s. **Done-when:** a host test holds the refusal rule; with the QMX off, Call CQ is refused and nothing is queued (field). |
| u4dw | <a id="u4dw"></a>TX watchdog: stop a runaway transmitter | **Safety.** Tries bound how many times each message and a CQ go out ([autoseq.md](architecture/autoseq.md), **Tries**), but nothing bounds continuous transmit on any path, nor TX across a QSO that keeps changing state. Cap both, and stop through `tx_scheduler_cancel()`. The policy is one `host_mock`-tested function; a fixed cap needs no UI. **Done-when:** host tests cover the cap and the no-progress rule; a forced runaway TX stops at the cap (field). |
| bfkb | <a id="bfkb"></a>Tune: the P4 stops it on high SWR | Tune with the antenna off ran past a second at SWR 9.98 on QMX 1_04_010, shown by both the app and the radio's display (operator, 2026-11-02), though a trip during a normal transmission is caught ([radio.md](architecture/radio.md), **SWR protection trips on a QMX**). Either the radio's protection is bypassed in its SWR Tune mode or Tune's power is under its 0.5 W floor. We need not separate the two, since the fix is the same: the P4 reads SWR during Tune, ends it above a limit, and the radio bar says why, as it does for a tripped transmission. Open design: which limit, the QMX's own Protection threshold (`MMProtection\|SWR threshold;`) or a setting of ours. **Done-when:** a host test pins the stop decision. Field: with the antenna off, Tune ends within a second and the radio bar names the reason; with the antenna on, Tune runs. |
| mtd6 | <a id="mtd6"></a>Per-radio settings, chosen by the radio's identity | A station with two radios (a QMX and an HL2, epic [knpp](roadmap/hl2-support.md)) needs bands, listen-only bands, IF trim, amplifier and transmit limits per radio. **Choices:** one `station.json`, written atomically (temporary file, then rename) with a last-good copy; per-radio settings in a section named by the radio's identity (the QMX's `UI;`, the HL2's MAC); call, grid and log stay station-wide; a radio never seen gets a section seeded from the current values; the web app names the attached radio in Settings; Port A's CONFIG messages unchanged. **By exception** (maintainer, 2026-11-03): a one-time conversion from `Station.txt` at boot, by a copy of today's parser frozen at its last version, deleted once both P4s have converted. After [vcng](#vcng). **Done-when:** host tests hold the parse, the atomic write, the fallback to the last-good copy and the conversion; two radios on the bench each come up with their own `active_bands` (field). |
| jqpm | <a id="jqpm"></a>Opening calls get at most 4 tries | Epic [qxy5](roadmap/smart-queue.md#jqpm). Answers to a repeated opening call fall off fast (the epic's **Evidence**); a constant caps REPLYING, every later stage keeps `tries`. **Done-when:** a host test shows REPLYING ends after 4 with `tries` at 6, after 2 with `tries` at 2, and after the entry's own count when one is set. |
| B88 | <a id="B88"></a>Hold the TX offset for the length of a QSO | `resolve_tx_offset()` re-rolls RANDOM (the default) per transmission. WSJT-X applies QSO-context AP decoding only within ~50 Hz of the partner's Rx/Tx frequency (`lib/ft8/ft8b.f90`), so our R-report and RR73 lose several dB on exactly the weak contacts that need them. **Fix:** roll once when a QSO starts, hold until it ends or is abandoned; keep per-TX re-rolls for an unanswered CQ. `resolve_tx_offset()` is in `poe_p4/main/tx_scheduler.cpp`. Reasoned from WSJT-X's source. Seen on air on 20 m (2026-11-10): D2UY's three R-reports went out at 2317, 702 and 1141 Hz and no RR73 came, though that cannot be put down to the offset. **Done-when:** one `resolve_tx_offset()` policy in a component, `host_mock`-tested (held from QSO start to end or abandon, re-rolled per TX for an unanswered CQ); [architecture/webapp.md](architecture/webapp.md) (**Screens**, waterfall) updated. |
| k33u | <a id="k33u"></a>Flag an unset P4 clock and set it on the next poll | The sidekick keeps no clock. A set during a slot's emit sends the uptime slot index, and the app labels it 1970. **Fix:** the sidekick flags the page when that epoch is before 1990; the page posts `/api/time` on the flag; a slot that started unset keeps a blank index. **Done-when:** page already open, reboot the P4; the clock is set on the next poll and no decode batch is dated 1970. |

| qauk | <a id="qauk"></a>AP decoding during a QSO | Written from the QEX paper (Franke, Somerville, Taylor 2020), not WSJT-X's code. In a QSO, autoseq knows most of the next message: our call, the partner's call, the expected report, RR73 or 73. Fixing those bits before LDPC is where WSJT-X gains several dB, on the weak replies that finish a QSO. It applies only within a few Hz of the partner's offset (WSJT-X's `napwid` is 50 Hz; pre-filled band-wide, noise decodes as RR73), so it adds a few LDPC tries. Band-wide "CQ ???" and "MyCall ???" are a later step, timed separately. The corpora have no QSO context, so the test is new. **Open:** whether the decode list marks AP decodes, as WSJT-X does. **Done-when:** a host test of synthetic QSO exchanges at falling SNR, partner supplied, gives the gain in dB and the false-decode rate on noise and on a wrong partner; P4 decode time measured; a QSO completes on a decode the SLOT line counts as AP (field). |
| kkap | <a id="kkap"></a>Decode: subtract decoded stations from the audio, around the QSO partner first | On a crowded slot we decode 6% of the stations within 30 Hz of a stronger one, against 90% in clear spectrum ([corpus](https://github.com/kb2slo/micro-ft8/releases/tag/corpus-2026-11-02)); lowering a decoded message's waterfall bins ([decode.md](architecture/decode.md), **Subtraction**) erases what shares them. Re-synthesise each decode, fit its time, frequency, amplitude and phase on the slot's audio, subtract, re-search: from the QEX paper's description, not WSJT-X's code. **First slice:** in a QSO, only the decoded stations overlapping the partner's 50 Hz, then a search there again, the partner first as epic [u8mc](roadmap/several-channels.md)'s order puts it; band-wide is the later slice. **Done-when:** on a host corpus, the share of busy-slot decodes within 30 Hz of a stronger one, measured; if it earns the slice, synthetic replies beside a strong station decode more often, host-measured, and the P4 cost is measured. |
